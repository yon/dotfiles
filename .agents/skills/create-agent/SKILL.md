# Create an agent

Use [the agent template](assets/agent.md) as a starting point. Replace its
placeholder metadata and guidance with the requested role; include only the
sections that help that role perform its task. Preserve its core principles
where applicable.

Give the role a distinct name and a specific description of when to use it.
Define responsibilities, boundaries, approach, and expected deliverables.

When a target harness is specified or clear from the task, inspect its existing
agent definitions and documentation, then adapt the role to its supported
format, metadata, and project or personal installation location. Include tool
restrictions or presentation fields only when supported and useful for the role.

If no target harness is established, produce a portable Markdown role definition
in the requested location or response. Do not assume a harness-specific directory
or claim the definition is installed. The template's metadata describes the role;
it is not a universal agent configuration schema.

Before finishing, remove unresolved placeholders and check referenced resources.
For a harness-specific definition, validate against that harness's requirements.

The template is an asset, not an installed agent definition.
